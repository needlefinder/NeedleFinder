# NeedleFinder 2026: second referee report and independent verification

22 October 2026. Manuscript: `vault/paper/manuscript.md`, lines 1–267 as inspected. Recommendation: **major revision requiring corrected evaluation, not editorial revision alone**.

## 1. Referee report

### Summary of the contribution

The manuscript combines an analytical dark-core detector, a multi-output volumetric network, slice-level message passing, and bundle-level classification/tip refinement for catheter reconstruction on T2-weighted MRI. It reports a substantial clinical annotation resource, comparisons on common folds, an adhesion subgroup, a second-observer comparison, and a useful negative-image experiment. Bundle-level reasoning on MRI is a plausible contribution. The supplied headline summary contains 970 matched reference trajectories out of 1,063, from 1,137 predictions, giving 88.18% pooled F1. These numbers are promising, but do not establish the manuscript's claims about unbiased generalization, one-patient learning, clinical equivalence, or the deployed system's joint speed and accuracy.

This review recognizes today's repairs: Table 3 now has a real export and algorithm-versus-observer rows; the figure generator reads measured error distributions and stored bootstrap intervals; the Xiao literature row now identifies the fully supervised result; baseline and synthetic training scripts are present. I do not repeat the earlier allegations that those scripts are missing, that the current human distribution is simulated, or that there are no algorithm-versus-observer data. Remaining problems include code-level validation leakage, incompatible result versions, unsupported experiment interpretations, and stale rendered assets.

### Major points

1. **The claimed patient-level out-of-fold protocol is not implemented as described.** Experimental Setup, line 136; Key Terms, line 48; Abstract, line 10. In `run_edelweiss_training.py:199–231`, the held-out `val_indices` determine the best checkpoint using Dice plus half the core recall. Lines 234–254 then export those same patients as OOF predictions. Baseline training also selects checkpoints on the held-out fold (`train_baselines_pmb2026.py:621–667,688–734`). This directly contradicts the assertion that test patients never enter model selection. Further, `run_synthbrachy3t_full.py` trains downstream models from globally precomputed OOF features: a training patient's upstream model can have been trained on the downstream outer-test patients. Excluding the current patient's own labels from its feature model does not isolate the complete stacked pipeline. **Fix:** define outer test folds once; perform checkpoint and hyperparameter selection entirely inside each outer training set; generate downstream training features by inner cross-fitting confined to that set; freeze all stages before outer testing. Document patient identity grouping, including any repeated acquisitions, and publish a fold/model dependency manifest. An index-modulo split alone cannot prove independent patients.

2. **A production export can overwrite OOF predictions; artifact provenance must be established before accepting any performance estimate.** Lines 136, 159, 245. `run_edelweiss_training.py:263–266` trains on all 54 cases and passes the first ten as `val_indices`. The reused training function writes `oof_case_00.npz` through `oof_case_09.npz` into the same output directory at line 245. This is a concrete overwrite path, not proof that the historical cache used for this manuscript was overwritten. In addition, the synthetic finalizer/exporter loads `/tmp/cached_ens_synth_oof_54.pkl`; the inspected benchmark scripts contain consumers but I did not locate its producer. **Fix:** use separate immutable outer-fold and production directories, forbid writes to existing evaluation artifacts, provide hashes and production commands for every cache, and regenerate the final results from an auditable run. Do not merely rename potentially contaminated files. Ground-truth-assisted preprocessing also needs removal or disclosure: `train_and_eval_unet3d.py:167` uses `k_lim_gt`, while `prepare_and_inspect_dataset.py:190–245` uses template annotation information and can fall back to a median reference-catheter base. Demonstrate the same crop can be obtained at deployment without reference traces.

3. **The few-shot curve does not measure the number of annotated patients needed by the entire method.** Abstract, lines 12–14; Results, lines 185–189; Conclusion, line 235. In `finalize_synthbrachy3t_benchmark.py:208`, only the clinical bundles used to fine-tune Stage 2B are restricted to the first *k* eligible cases. Upstream features remain those of the larger-data pipeline, and line 240 blends with `base_oof_scores`, a classifier trained using the full clinical training set. At *k*=1, the formula gives 84.4% synthetic-adapted score and 15.6% full-data clinical score. The no-synthetic comparison likewise retains full-data OOF inputs and blends its adapter. More seriously, the *k*=0 branch at lines 172–201 applies confidence thresholds, geometric gating, smoothing, and deduplication to Stage 0 trajectories; it never calls the pretrained synthetic transformer. The 75.1% result therefore cannot demonstrate synthetic-to-real transfer. **Fix:** either label the present experiment “Stage 2B adaptation budget with fixed full-data upstream models and ensemble,” or retrain every label-dependent component within each budget, removing the full-data blend. Include a genuinely synthetic-only inference branch, repeat random training-patient selections, and show variability over selections and training seeds. Five folds of 54 patients contain 43 or 44 training patients, not uniformly 43. The current largest-budget point simply copies the full result.

4. **One JSON contains incompatible versions of the baseline results and one central significance claim does not reproduce.** Results, lines 175–179, 187; Table 2. In the unified source, the PMB-inspired baseline summary has 924 matches, but its saved error array has 941; the clDice summary has 961 matches, but its error array has 975. The paired F1 tests use arrays belonging to this inconsistent result collection. I reproduced the main-versus-PMB, clDice, and Xiao F1 p-values from the 54 saved patient F1 values. However, main versus the no-synthetic IRGM/Poly3 variant gives Wilcoxon statistic 324 and **p=0.0180116**, versus stored statistic 142 and **p=0.000064202**. The stored comparator patient mean is also different from the array mean. This is not resolved by choosing whichever result is more favorable. **Fix:** export summaries, patient counts, match identities, distributions, confidence intervals, tests, and all figures in one transaction from identical prediction objects. Add consistency assertions. Recompute every difference and significance statement after points 1–2 are addressed.

5. **The baselines are useful adaptations, but are not faithful implementations of the named methods.** Lines 138–140, 175–177, 225; Table 2 footnotes a–c. The PMB-inspired postprocessor in `train_baselines_pmb2026.py:333–450` uses slice peaks, greedy linking, and polynomial fitting, not the stated DBSCAN/Hough/spline pipeline. The clDice baseline uses a 2D distance-transform ridge plus linking (`:474` onward), not the claimed 3D morphological skeletonization. The Xiao adaptation (`run_xiao2026_and_fewshot_benchmark.py:197–379`) uses connected-component/distance-transform candidates, local PCA, and synchronous assignment, but not an actual direction-constrained 3D Hough initializer. Its geometric gate is not the published learned IRGM. The published CT model is not directly tested on MRI. **Fix:** rename these as explicitly described adaptations, or implement and validate the published stages faithfully. Give all methods comparable training/validation and postprocessing tuning budgets. Include a strong segmentation baseline with the same candidate cleaning and smoothing, and controlled swaps of candidate generation, linking, pruning, and tip refinement. The present ablation changes synthetic training and tip-aware modeling together, so its gain cannot be assigned solely to pretraining. Novelty should be the demonstrated MRI combination and bundle/tip model, not categorical failure of all voxel or tracking methods. Bibliographic verification of the named works is recorded in section 3.

6. **The low false-alarm headline is from a different pipeline.** Abstract, line 12; Results, lines 209–211; Discussion, line 231; Conclusion, line 235; Table 4. The 18 false tracks / 48 scans = 0.375 result belongs to `3_stage1_unet_with_stage0_sym_gate_only`, explicitly **without** the graph transformer. The evaluated unified transformer variant instead gives 225 false tracks (4.688/scan) at 50% and 188 (3.917/scan) at 60%. Those variants should not automatically be identified with the final synthetic, tip-aware pipeline either. The Results now correctly says the radial gate is an alternative, but the Abstract and Conclusion attribute its result to the headline method. **Fix:** run the identical frozen final pipeline on positive and negative scans, and report both sensitivity and false alarms with and without this gate. Include scan-level confidence intervals and the threshold-50 row. Forty-eight catheter-free male prostate scans test rejection on different anatomy; they do not demonstrate accuracy on external catheter-bearing gynecologic scans, scanner invariance, or zero hallucinations. Verify field strength before retaining “3T” in Table 4.

7. **The detection metric can reward incomplete trajectories and the assignment implementation does not maximize valid matches.** Lines 144–149; Results, line 179; Table 2. `evaluate_unified_apples_to_apples.py:72–123` measures mean in-plane error only over the common z-extent, requiring little shared length. A short correctly placed fragment can therefore count as a detected whole catheter while having a very poor tip. The implementation solves an unrestricted assignment and then rejects pairs above 3.5 mm. This is not necessarily maximum-cardinality thresholded matching: for the illustrative cost matrix `[[0.1,3.4],[3.4,3.6]]`, minimizing total cost first leaves one accepted pair, whereas the off-diagonal assignment gives two valid pairs. This is a constructed counterexample, not an observed patient result. **Fix:** use threshold-forbidden edges and explicit unmatched assignments with a stated cardinality objective; add shared-length coverage and tip/completeness endpoints; perform threshold sensitivity analysis. Keep comparison with the old metric to show the impact. Clarify the separate 8 mm preliminary rejection in line 147, the max-cranial-z tip convention, and how truncated-field-of-view tracks are scored. Fifty points uniformly sampled in z are not uniform arc-length sampling; check convergence or use point-to-segment distances for 3D curve metrics.

8. **The statistical unit is appropriate, but the estimands, multiplicity, and uncertainty need clearer treatment.** Lines 151, 179, 185–189; Table 2. Patient-level bootstrap and paired patient-level Wilcoxon are preferable to treating all catheters as independent. The headline pooled F1 CI in the source is 86.35–90.05%; I reproduced that interval by resampling patient counts. Nevertheless, the pooled F1 difference is not the same estimand as a signed-rank test on patient F1. Tip tests use per-patient mean errors, whereas the text places p-values next to pooled medians. The evaluator imputes fixed errors when no match exists (shaft 3.5 mm, 3D distance 10 mm, HD95 and tip 20 mm, lines 293–307); these rules and their frequency are not described. **Fix:** prespecify a primary endpoint and comparison; report paired patient effect sizes and CIs, the test's estimand, zero/tie handling, imputation counts and sensitivity analyses, and a multiplicity strategy. Label bootstrap intervals as uncertainty conditional on these fitted OOF models; they do not include model retraining or few-shot selection uncertainty, and shared training sets induce dependence. Document when 50% was fixed: the benchmark scripts expose sweeps of blending, tip refinement, and thresholds, so pre-specification requires a dated protocol or an untouched test set.

9. **Agreement with experts is not evidence of clinical equivalence or a nearly correction-free workflow.** Lines 49, 201–203, 229–235. The new common-loader Table 3 is valuable. It does show smaller shaft disagreement against CY, the training annotation convention. Against LB/AMe, tip discrepancy is 4.76 mm versus 3.20 mm between humans. Different rows match different catheter sets, and proximity to one annotator is not accuracy against an independent physical truth. The phrase “within 0.05 mm” also does not cover the shaft IQR (0.6045 versus 0.5113 mm). **Fix:** use common matched triplets for paired comparisons, document independent/blinded annotation and any software assistance, quantify uncertainty, and use a prespecified noninferiority margin if claiming equivalence. Present human disagreement as a reference distribution, not an absolute error floor. Separate short, truncated, and full-length catheters. A timed correction study and dose recalculation are needed for the asserted 1–2 minute verification workflow.

   The present matched-catheter tip distribution deserves much greater prominence: mean 7.90 mm, median 2.61 mm, P95 36.10 mm; 196/970 (20.2%) saved tip errors exceed 10 mm. There are also 93 missed reference trajectories and 167 unmatched predictions, about 1.72 misses and 3.09 false predictions per patient. The 0.46 mm conditional in-plane median cannot establish compliance with the overall ≤2 mm reconstruction recommendation of TG-303 (DOI **10.1002/mp.15713**, verified through Crossref/PubMed and the publisher's full report). Expand the limitations beyond the stated two to include selection bias, reference dependence, incomplete tracks, domain shift, study size, and absent clinical/dosimetric validation.

10. **The manuscript does not describe one reproducible architecture and inference configuration.** Methods, lines 87–128; computing, lines 155–159; Results, line 213. Examples: the supplied initial U-Net block is 3×3×3 rather than 1×3×3; the actual loss is not the reported positive-weight-12 BCE and direction MSE; the “obturator” target is built from short trajectory labels, not a central-organ segmentation. Final synthetic decoding uses weight 0.60, while the text says 0.55, and the production implementation uses another value. Long-only evaluation lowers the effective threshold to 42.5% when the row is labeled 50%. Production Stage 1 strides and crops large volumes, whereas cached OOF inference runs a different path. **Fix:** pin the evaluated code/model/configuration, derive the Methods from it, explicitly enumerate the pipeline variants, and evaluate accuracy and runtime using the same deployed inference path. The architecture audit in section 2 gives exact discrepancies; these are not cosmetic details.

11. **The timing and rendered figures are not yet sufficiently evidenced.** Title; Abstract, lines 12–14; Results, lines 191–193, 211–213; Discussion, line 229. A 1.25 s GPU mean and 2.74 s CPU mean cannot support “Sub-Second”; the quoted high-resolution mean of 3.47 s contradicts “under three seconds.” The latest log says 20 standard and 34 high-resolution cases: weighting the reported 1.20 and 3.47 s means gives 2.629 s, not 2.74 s; weighting the figure source's Stage 1 subgroup values of 0.55 and 1.02 s gives 0.846 s, not 0.96 s. The figure script contains literal timing constants; the opened runtime CSV is older, and I did not find the per-case timing records substantiating these replacements. Also, the corrected qualitative export resides in `vault/sources/table3_export/`, while the figure generator looks in `vault/reports/figures/data/`; its prediction NPZ is absent there. The inspected rendered Figure 5 still labels the first bundle “26 cath.” rather than displaying the new 27-prediction overlay. **Fix:** publish per-case uncached timings with CPU model, threads, initialization/I/O boundaries and repeats; regenerate all PDFs from pinned inputs with failures on missing files; inspect the actual submission PDF. Cross-paper runtime ratios need hardware and scope caveats, and the optimized PMB baseline is only about 5.4 times slower than the claimed CPU time.

### Minor points

1. **Rounding and obsolete observer values:** line 203 and Table 3: 0.7149 rounds to 0.71, not 0.72; 0.4949 to 0.49, not 0.50; 0.5248 to 0.52, not 0.53; 0.6045 to 0.60, not 0.61. Table 1 footnote c still says 481 pairs rather than 464. Line 229 still says 0.51 mm. Table 2's main shaft P95 1.3149 rounds to 1.31, not 1.32. Generate all display values directly from the chosen source.
2. **Superlatives:** line 179's “most accurate on every metric” is contradicted by Table 2: the PMB-inspired baseline has lower matched-shaft error; in the adhesion subgroup clDice has higher recall. Lines 65/223's largest-cohort claim needs a defined scope and search date; the manuscript itself lists an earlier 54-patient MRI study. Use “highest pooled F1 among these evaluated configurations” when the corrected analysis supports it.
3. **Terminology:** lines 87–93: Stage 0 has fixed numerical parameters and operates over an ROI. Call it “analytical, with no learned weights,” give the complete response formula including its exponent and constants, and distinguish radius, diameter, image smoothing, and ROI selection. “Responds only” to round dark spots is stronger than this detector can guarantee.
4. **Graph explanation:** line 118's assertion that a pairwise graph network cannot penalize a kink is too strong: multi-layer pairwise message passing can acquire multi-hop context. Describe precisely the incoming/outgoing edge aggregation and what it adds; do not equate it with an explicit triplet-curvature objective unless one is implemented.
5. **Literature table:** line 219 / Table 5 mixes means, medians, RMS distances, Hausdorff distances, signed tip offsets, scan counts, patients, fractions and test-set catheters. Add metric/denominator columns and correct the specific entries in section 3. Do not bold a cross-hardware runtime as a comparable “best.”
6. **Figure distributions:** line 171 / Figure 3: the plotting code truncates shaft and tip values for density/scatter displays (2.5 and 15 mm respectively), while reporting full-distribution summary labels. The unshown-outlier count is computed but not displayed. Show an inset/full-range plot or clearly mark clipping and counts; the tip tail is clinically important.
7. **Scope of synthetic data:** lines 10, 67, 128, 225: only the bundle component receives these synthetic feature bundles. “3T” is a dataset/model name, not a simulated field-strength effect. The generator starts with 12–23 long shafts and adds twins; the resulting long-shaft count can be 15–29. State initial versus final counts, and replace “more configurations than any clinical dataset” with a bounded statement about this training set.
8. **Software and reproducibility:** lines 155–159, 241–245: distinguish training, evaluation/export, and ONNX-producer versions. An ONNX header does not establish the training environment. Remove machine-specific absolute paths and temporary-cache dependencies; provide a command producing every submitted artifact from a documented manifest. Ethics approval, exact patient identity, acquisition ranges, and historical annotation independence cannot be independently established from summary JSON alone.

## 4. Readability for non-specialists

The Plain-Language Summary and Key Terms are useful, and the basic progression from dark spots to trajectories to a whole implant is understandable. The main readability problem is that simplified explanations currently hide qualifications essential to the conclusions.

| Location | Problem | Concrete revision or example |
|---|---|---|
| Title2 | “Sub-Millimeter, Sub-Second” sounds like an all-point accuracy and end-to-end runtime guarantee. Neither is established. | Use a descriptive title such as “NeedleFinder 2026: Automated Catheter Reconstruction on T2-Weighted MRI Using Image and Bundle-Level Features.” Restore numerical adjectives only with a clearly scoped endpoint. |
| Plain summary 19 | Generalizes a 1–2 mm error to a 10% dose change. Readers may interpret this as a universal conversion. | “A small tracing error can change the planned dose, especially near organs where the dose changes rapidly with position.” Give a study-specific example in the technical Introduction, with direction and dose endpoint. |
| Plain summary 23 | “Dark all the way around” can sound as though the surroundings are dark; the detector actually seeks a darker centre surrounded by brighter tissue. | “The first step finds small dark centres with brighter tissue around them. It reduces responses to broad edges, but can also respond to blood vessels.” |
| Plain summary 23 / Methods106 | Claims a network understands or segments the obturator; actual auxiliary labels are short tracks. | Describe what was labeled and predicted in ordinary language, then define the obturator separately as the applicator component. |
| Plain summary 25 | “On average, half a millimeter” substitutes an average for a median and does not say this is in-plane error among matched shafts. | “For the tubes that could be matched to an expert trace, the median sideways shaft discrepancy was 0.46 mm; the median discrepancy at the tip was 2.61 mm.” Explain median as the middle value if retained in a lay summary. |
| Plain summary 25 | “Closer than two experts” omits reference-team dependence and larger tip discrepancy against the second team. | “Agreement along the shafts was similar to the disagreement between the two tracing teams. Tip positions were less reliable.” Avoid claiming statistical equivalence. |
| Plain summary 25 | “Under three seconds” contradicts the stated 3.47 s high-resolution mean, and the raw timing evidence is unavailable. | After timing reconciliation: “Processing took a few seconds on the tested computer; larger scans took longer.” |
| Plain summary 25 | “Rare miss” and a simple verification step understate workload. Main counts imply roughly 2 missed tubes and 3 extra predictions per scan on average; tip outliers add work. | State these as approximate study averages, explain that errors vary by patient, and say that clinical review/correction time has not yet been measured. |
| Key Terms46 | Harmonic mean remains jargon to many readers. | Add: “A method must both find real tubes and avoid inventing extras to receive a high F1 score.” A worked example with 10 real tubes, 8 correct detections and 2 false detections gives 80% recall, 80% precision and 80% F1; label this as an illustration, not study data. |
| Key Terms48 | OOF explanation is good in principle, but is currently factually too strong. | After fixing the experiment, add that checkpoint choices and all later graph models must also exclude each test patient's information. |
| Key Terms49 / line 201 | “Practical floor” and “clinically equivalent” suggest human disagreement defines truth or a validated acceptance threshold. | “This measures disagreement between observers and provides context for algorithm–observer disagreement.” |
| Methods99 | A .3 mm “catheter hole” confuses pixel size and a roughly 2 mm catheter diameter; a factor-of-three loss of detail is not a measured point-spread result. | Say that coarser resampling may remove fine in-plane information. Separate physical catheter diameter, pixel spacing and effective spatial resolution. |
| Methods116–118 | “Triplet-collinearity message passing,” directed edges and attention aggregation arrive too densely. | Add: “Two consecutive links can each look plausible yet form an abrupt bend when considered together. The model uses information from neighboring links when scoring them.” Follow this with the exact implemented update. |
| Methods124–128 | Token, logit, IRGM, Poly3 and tip surface require repeated translation. A coherent tip surface is also a modeling assumption, not a biological law. | Define a token as a list of measurements for one candidate tube; say “score” before “logit”; call Poly3 “a cubic curve fit.” Include one true-tube and one vessel candidate with their relevant measurements. |
| Methods128 / Results189 | “Synthetic-to-real” invites the reader to imagine synthetic MRI scans and end-to-end zero-shot learning. | Explain that the generator creates lists of candidate-curve measurements, not MRI images. Distinguish synthetic bundle training from supervised image-feature extraction. |
| Results171/179 | Shaft error,3D curve distance and HD95 are easy to conflate. | Include a short example: a fragment may follow the middle of a true tube closely yet end far from its tip. Label it an illustration. This explains why small shaft error and large tip/curve error coexist. |
| Results175/225 | “Nothing rejects them,” “cannot bridge,” and “every vessel blob” are absolute claims about broad families. | Attribute the observed fragmentation/false tracks to the tested implementation and quantify audited failure categories. |
| Results203 | The paragraph compresses rates, means, medians, tails, observer asymmetry and clinical interpretation. | Split into: human agreement; model versus each observer; limits of comparing these distributions. Define the denominator before giving each percentage. |
| Results209 / Table 4 | “Specificity” can be mistaken for voxel specificity or a clinically validated diagnostic test. | Use “false trajectories per scan” and “fraction of catheter-free scans with no false trajectory.” State the pipeline beside each result. |
| Discussion231 | “Two limitations remain” and promised <1.5 mm tips sound conclusive despite unresolved validation and no sequence experiment. | Expand the limitations and describe thin-slice/alternative sequences as future tests, without a predicted numerical outcome. |

A defensible interim lay-summary result paragraph, **pending corrected validation and timing**, would be:

> In the saved evaluation, the software found about 91% of the reference tubes, and about 85% of its reported tubes could be matched to a reference trace. Among matched tubes, the median sideways shaft discrepancy was 0.46 mm and the median tip discrepancy was 2.61 mm, with some much larger errors. These results suggest the software could assist tracing, but clinicians would still need to check missing tubes, extra tracks and tube ends. Its effect on correction time and treatment plans has not yet been measured.
